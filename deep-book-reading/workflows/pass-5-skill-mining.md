# PASS 5 — Skill mining

## Procedure

1. Scan Method, Framework, Rule, Pattern, Principle, and linked Limitation units across all chapters.
2. Group units by the practical problem they solve, not by chapter.
3. Score each group with the Skillability rubric and apply automatic vetoes.
4. For approved candidates, define trigger, inputs, outputs, decision points, steps, boundaries, failure modes, and validation scenarios.
5. Generate one Agent Skill per coherent trigger/problem. Keep detailed book evidence in `provenance.yaml` or direct references so the main Skill stays concise.
6. Test the Skill on a positive scenario, boundary case, counterexample, and fidelity/attribution trap.
7. Compare every prescriptive rule against original Source, Evidence Ledger, and limitations. Downgrade claims that became stronger during generalization.

## Exit gate

Every generated Skill has an approval score, source-backed provenance, boundaries, and passing tests. Rejected/held candidates remain recorded; absence of generated Skills is a valid result.
