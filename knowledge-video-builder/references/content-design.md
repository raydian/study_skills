## Source Reduction

Convert the source into a video-native explanation. Extract:

- one audience and one learning question;
- one direct answer or learning outcome;
- two to four key ideas;
- one representative example, analogy, demonstration, or case;
- one likely misconception and its correction;
- one takeaway, memory aid, or action checklist.

Keep supporting details only when they help the viewer understand, remember, judge, or act. Move extensive references, large tables, secondary examples, and deep derivations to the source article or downloadable material.

## One-Frame Cover And Separate Hook

The cover and hook are two separate pages with different jobs:

- frame `0`: one-frame cover for topic identity and thumbnail capture;
- frame `1` onward: independent hook page for attention and relevance.

Require frame `0` to contain:

- a large video title or topic as the dominant element;
- enough context to identify the knowledge category;
- one highlighted key phrase at most;
- a finished, readable static layout.

The cover exists for exactly one frame. Do not attach narration, subtitles, entrance motion, exit motion, or a transition overlap to it. Hard-cut at frame `1` to a visually distinct hook page.

The hook page must not duplicate the cover. It should present a concrete question, conflict, consequence, misconception, decision test, or counterintuitive fact. Let it occupy approximately five seconds, then follow with a direct answer, answer boundary, or route preview within `5-15` seconds of the video start.

Useful hook types:

- **Concrete question**: “为什么越努力记，反而忘得越快？”
- **Misconception correction**: “平均数相同，不代表两组数据一样稳定。”
- **Consequence**: “忽略这一步，后面的计算可能全部失效。”
- **Decision test**: “如果这三个条件缺一个，先别急着下结论。”
- **Counterintuitive fact**: “看起来更快的方法，可能最浪费时间。”

Avoid:

- “大家好，欢迎来到……”;
- black, blank, logo-only, or series-title covers;
- a cover whose main title is missing at frame `0`;
- holding the cover for two or more frames;
- fading, morphing, or animating the cover into the hook page;
- reusing the same text hierarchy and composition for both cover and hook;
- vague hooks such as “这个问题非常重要”;
- exaggerated fear, guaranteed outcomes, or unsupported numbers;
- withholding the useful conclusion until the end.

## Shared Narrative Arc

Use this as the default focused-explainer arc. Author cue durations during planning and keep them editable for later human voice production.

| Stage | Approximate range | Purpose |
|---|---:|---|
| Standalone cover | Frame 0 only | Show the video title or topic in large type; no narration or subtitle |
| Hook page | Frame 1 to about 5s | Name a concrete question, conflict, consequence, or misconception on a separate page |
| Direct answer | 5-15s | Give the conclusion, learning outcome, or scope |
| Why it is confusing | 15-35s | Expose the misleading shortcut or missing link |
| Route map | 35-50s | Preview two to four key ideas |
| Core explanation | Main body | Explain one idea per scene with visible structure or evidence |
| Example or case | Late body | Apply the concept, rule, or method |
| Misconception check | Before recap | Correct the most likely wrong takeaway |
| Takeaway or action | Final 20-35s | Give a memory aid, procedure, or concrete next action |
| Closing | Final 3-6s | Restate one conclusion and point to the next related question |

## Route Selection

Choose one primary route. Combine routes only when the source genuinely requires it, and keep one route dominant.

### Concept Or Mechanism

Use for definitions, principles, causal mechanisms, and scientific or humanistic explanations.

Sequence: familiar phenomenon → core question → plain-language model → formal concept → worked example → misconception check.

### Rule Explainer

Use for policies, standards, procedures, scoring, constraints, and eligibility rules.

Sequence: confusing terms → plain-language definition → condition map → example → boundary and verification checklist.

### Method Or Process

Use for study methods, problem-solving procedures, tutorials, and operational workflows.

Sequence: common failure → target outcome → ordered steps → demonstration → failure checks → reusable checklist.

### Comparison

Use when the viewer must distinguish alternatives, concepts, approaches, products, or choices.

Sequence: shared baseline → decisive dimensions → side-by-side evidence → scenario fit → selection rule.

### Case Analysis

Use for representative events, learner problems, decisions, diagnoses, or applied reasoning.

Sequence: case facts → core conflict → missing information → candidate explanations or options → evidence comparison → reasoned conclusion.

### Data Interpretation

Use for charts, trends, experiments, surveys, and quantitative evidence.

Sequence: question → what the data measures → visible pattern → alternative explanation → valid conclusion and boundary.

## Teaching Language

- Use plain language first, then introduce the formal term.
- Use short transitions: “先看现象”“再找原因”“最后用一个例子验证”.
- Define symbols, abbreviations, and specialist terms on first use.
- Distinguish facts, interpretations, illustrative cases, and opinions.
- Use conditional wording for claims with scope or prerequisites.
- Avoid unexplained jargon, slogans, absolute recommendations, and artificial suspense.
- Avoid visual-direction phrases so the editorial script works in both aspect ratios.

## Scene Quality Gate

Require every scene to answer:

1. What should the viewer understand, remember, or be able to do after this scene?
2. What visual evidence or structure makes that understanding easier?
3. Which script or caption cue triggers each visual change?
4. Can the same meaning be reflowed clearly in both aspect ratios?
5. What teaching purpose does the motion serve?
6. Does the transition communicate continuity, progression, contrast, reveal, or a topic boundary?

Merge or remove scenes that only decorate, repeat the subtitle, or restate the source without visual explanation. Split scenes that require paragraph blocks, dense grids, or several competing focal points. Require separate horizontal and vertical layout descriptions; the vertical description must reduce simultaneous content and use stacked or sequential presentation.

## Explanation Depth Gate

Do not turn a detailed source into a sequence of titles. For every core idea, write and storyboard three layers: (1) conclusion, (2) reason, definition, condition, or causal link, and (3) a consequence, comparison, data-reading cue, representative example, or next action.

Use short explanation text when a graphic alone would be ambiguous. Preserve decisive distinctions and reasoning; cut repetition and secondary detail, not the explanation itself. Name illustrative cases in plain language, such as “选科四步判断法”; do not invent jargon the audience must decode.
