# 章节笔记通用规范

## 用途

为高中学生生成可长期复习的章节笔记。章节笔记不是教材摘抄，而是基于教材章节重新组织、适合学习和复习的讲解稿。

## 目录约定

输出放在对应学科目录下：

```text
high_school/<学科>/章节笔记/<章节名>/
```

一个文件夹对应教材中的一个真实章节。不要混放学科，也不要把所有章节平铺在 `章节笔记/` 下。

## 文件约定

一个 Markdown 文件对应一个真实子章节的知识点讲解。

示例：

```text
1.1 集合的概念.md
2.3 二次函数与一元二次方程、不等式.md
第一节 物质的分类及转化.md
```

不要创建只复制教材原文的文件。除非用户明确要求，否则不要在 `章节笔记/` 中创建 `原始课本素材.md`。

可以在章节文件夹中增加章节开头或章末的整合文件，例如 `章首 学习导图.md`、`章末 整理与提升.md`。这类文件用于章节整体结构梳理、跨小节关系、综合考点和整体知识图，不替代各子章节学习笔记。

## 源文到子章节的拆分协议

拆分前先建立“章节/小节清单”，再生成文件，不要边读边按页码随意切割：

- 教材中的 `第一节`、`第二节`、`1.1`、`1.2` 等真实教学单元各自生成一个 Markdown 文件，文件名尽量保留原小节序号和标题。
- `问题研究`、专题探究等如果包含独立材料、问题链和结论，可作为同一章节目录下的补充独立笔记，例如 `章末问题研究 火星基地.md`；短小的 `活动`、`思考`、`案例`归入所属小节，但必须保留其知识价值。
- 不得按页码、插图、练习题块或装饰性标题拆分，也不得把多个真实小节合并成一个“本章摘要”。
- 每个拆分文件都必须保留完整的章节笔记结构和源文核心内容；拆分只改变边界，不降低讲解、例题、练习和图表信息的完整度。
- 生成或修正拆分结果后，必须同步更新唯一的 `章首 学习导图.md`，列出每个实际文件及其前后置、递进、比较或应用关系。

## Obsidian 与 Quartz 元数据规范

每篇新增或修改的子章节笔记必须以 YAML frontmatter 开头。最少使用以下字段：

```yaml
---
title: "1.2 集合间的基本关系"
description: "系统讲解子集、真子集、集合相等和空集，掌握集合关系的表示、判断方法与常见易错点。"
aliases:
  - "集合间的关系"
tags:
  - "学科/数学"
  - "内容类型/章节笔记"
  - "章节/集合与常用逻辑用语"
  - "知识点/子集"
  - "知识点/真子集"
  - "知识点/集合相等"
  - "知识点/空集"
draft: false
---
```

字段规则：

- `title`：使用准确、可独立理解的小节标题，供 Obsidian、Quartz 页面标题和搜索结果使用。
- `description`：用自然语言概括本节对象、多个核心知识点、学习收益和主要题型；保持具体、独立，避免关键词堆砌。Quartz 将它转换为 HTML description、Open Graph 和 Twitter 描述。
- `aliases`：只写真实、常用且无歧义的别名；没有合适别名时写 `aliases: []`，不能制造别名。
- `tags`：必须为 YAML 列表并使用带 `/` 的分层标签，供 Obsidian 标签体系、Quartz 标签页面和 Graph 标签节点使用。
- `draft`：使用 YAML 布尔值 `false` 或 `true`，不能写成字符串。
- `socialDescription`：仅在社交分享摘要确实需要不同于 `description` 时添加。
- 不默认添加 `keywords`；当前 Quartz 页面头部不消费该字段，且它不能替代准确的标题、摘要、正文和内部链接。

## 知识点标签图谱规则

知识点是标签图谱的核心，学科、章节和内容类型标签只承担辅助分类。

每篇子章节笔记必须先从实际内容中提取多个可独立学习、复习、检索和关联的核心知识点，再配置标签：

- 至少包含 2 个 `知识点/` 标签，通常包含 3–8 个；由实际知识密度决定，不能用其他维度标签代替。
- 每个 `知识点/` 标签必须能在正文中找到对应的完整讲解，不能只在 frontmatter 出现。
- 使用稳定、具体的概念名称，例如 `知识点/子集`、`知识点/真子集`、`知识点/集合相等`、`知识点/空集`。
- 同一概念跨章节或跨栏目出现时复用同一名称；先检索已有笔记，避免因教材措辞不同而新造同义标签。
- 不使用 `知识点/本节重点`、`知识点/重要概念` 等空泛名称，不拆词、不堆近义词、不为满足数量要求制造标签。

可用标签维度限于：

- `学科/`
- `内容类型/`
- `教材/`
- `章节/`
- `知识点/`
- `题型/`
- `能力/`
- `实验/`
- `主题/`

## 三层知识图谱规则

章节笔记同时使用三种互补结构：

1. `知识点/` 标签形成跨笔记的核心概念聚类；Quartz 会把标签显示为图谱节点，并连接所有使用该标签的笔记。
2. `章首 学习导图.md` 作为章节 MOC，形成教材层级和本章知识主线。
3. Wikilink 表达知识点之间的前置、递进、并列、对比、因果、推导、方法迁移和题型应用关系；Quartz Backlinks 自动呈现反向链接。

当生成或更新一个真实章节时，必须创建或维护唯一的 `章首 学习导图.md`：

- 使用同样规范的 frontmatter 和多个知识点标签。
- 列出并链接本章所有实际存在的子章节。
- 汇总本章核心知识点，并链接到承载该知识点的具体笔记或标题。
- 用自然语言说明知识点之间的关系，不能只罗列文件链接。
- 不替代子章节笔记，也不与 `章末 整理与提升.md` 重复建设多个章节索引。

## 双向链接规则

每篇子章节笔记必须在 H1 标题之后、九个必需学习栏目之前增加 `知识关系导航`。关系行按实际情况选择，不适用的行直接省略，不能写“无”：

```markdown
## 知识关系导航

- 所属章节：[[章首 学习导图|集合与常用逻辑用语]]
- 前置知识点：[[1.1 集合的概念#集合的表示方法|集合的表示]]
- 后续知识点：[[1.3 集合的基本运算#交集与并集|交集与并集]]
- 对比知识点：[[1.2 集合间的基本关系#子集与真子集|子集与真子集]]
- 相关知识点：[[1.4 充分条件与必要条件#集合视角下的条件关系|条件关系]]
- 相关方法：[[集合关系判断方法]]
- 相关专题：[[子集与集合关系专题]]
- 配套训练：[[集合关系题库]]
```

链接边界：

- 每篇笔记至少包含一个可靠 Wikilink；通常先链接所属章节 MOC，再链接真实相关的知识点。
- 默认只链接已存在或本次任务同时创建的 Markdown 文件，不创建指向未来文件的悬空链接。
- 优先链接具体知识点标题，使用 `[[文件名#标题|显示文字]]`；同名文件可能歧义时使用仓库内相对路径限定目标。
- 前置、后续等学生需要直接阅读的关系可以显式互链；一般反向关系由 Obsidian 与 Quartz Backlinks 自动呈现，不机械复制所有链接。
- 正文在关系真实发生的位置加入带语境的 Wikilink，并用句子说明关系类型；禁止只在文末堆砌链接。
- 如果找不到任何可靠目标，先创建或更新本章 `章首 学习导图.md`，再从子章节链接到它；不能为了满足规则制造无意义链接。

## 必需模板

每个子章节文件必须按以下顺序使用九个顶层栏目：

```markdown
---
title: "小节序号 小节名称"
description: "概括本节多个核心知识点、学习收益和主要题型。"
aliases: []
tags:
  - "学科/<学科>"
  - "内容类型/章节笔记"
  - "章节/<章名>"
  - "知识点/<知识点一>"
  - "知识点/<知识点二>"
draft: false
---

# 小节序号 小节名称

## 知识关系导航

## 本节学习目标
## 核心知识点讲解
## 重点梳理
## 难点突破
## 例题讲解
## 易错点整理
## 考点考证点整理
## 练习题
## 练习题答案
```

## 栏目要求

- `本节学习目标`: 说明学生学完后应理解、计算、判断、证明或应用什么。
- `核心知识点讲解`: 用通俗语言解释概念、公式、规则、符号、适用范围和意义。
- `重点梳理`: 提炼必须记住的结论、公式、流程和关键词。
- `难点突破`: 解决常见概念障碍、隐藏条件、推导过程或转化关系。
- `例题讲解`: 包含典型例题的题目、分析、步骤、答案和反思。
- `易错点整理`: 列出常见错误、错误原因和避免方法。
- `考点考证点整理`: 按一个个具体考点整理。每个考点必须包含：考点名称、常见出题思路、题目通常给出的条件或材料、解答时必须写出的关键回答要点或解题步骤、常见扣分点。不能只给出一句考点描述。
- `练习题`: 包含基础、巩固和提升练习；如果源文/课本中本小节有练习题、思考题、探究题、课后题或“练习与应用”，必须把对应题目收录进来，不能只用自拟题替代。
- `练习题答案`: 给出每道题的答案和解题说明，包括关键依据、解题步骤、必要公式/方程式、答题模板或评分要点，不只给最终字母或数字。

## 质量规则

- 面向正在学习本小节的高中学生写作。
- 以教材内容为来源，但要改写为学习指导。
- 不得为了压缩篇幅而省略本小节的核心知识点、关键定义、重要结论、必要推导、典型例题、实验/材料/图表信息或教材明确强调的学习要求。
- 写作前先从源文提取本小节的知识点清单；成稿后逐项核对，确保每个核心要点都在对应栏目中被解释、梳理或训练到。
- 如果源文包含多个并列知识点、公式、概念辨析、实验步骤、文本段落层次或史实线索，必须逐项覆盖，不能只选取其中最常见或最容易讲的部分。
- 例题必须完整讲解，不跳过关键步骤。
- 涉及公式、化学式、离子符号、数学符号或短方程式时使用 Markdown/LaTeX 保留；正文、表格、列表中的行内符号必须用单个 `$...$` 包裹，单独成行展示的重要公式才用 `$$...$$`。
- 适合比较的内容优先使用表格。

## 内容完整性规则

章节笔记可以重组和改写教材表达，但不能削弱教材的知识覆盖。每个子章节文件都要做到：

- 覆盖源文标题、小标题、正文讲解、图表/实验/材料说明、例题和重要旁注中的核心学习内容。
- 对教材出现的关键术语、概念边界、条件限制、公式符号、步骤流程、结论适用范围和学科方法给出明确说明。
- 对无法直接展开的图片、图表或实验材料，至少用文字说明其承载的知识点；不要只保留 `[图片]` 占位。
- 对教材练习、探究、思考题中承载的新方法或易错点，纳入 `例题讲解`、`易错点整理` 或 `练习题`，不要整块丢弃。
- 如果源文信息不足、图片缺失或 OCR 质量影响理解，必须在笔记中标注“需回看原文/图片确认”的具体位置，而不是假装已覆盖。

## 图片注释规则

章节笔记需要图文并茂。生成或整理笔记时，先分析整篇笔记结构，在最适合图示辅助理解的位置插入 HTML 图片注释。图片注释用于后续生成图片，也会作为图片说明保留，不能删除。

图片处理分为两个连续阶段：

1. **笔记阶段**：先从源文建立图表/地图/实验/照片/流程图等视觉单元清单，保留图号、图题或源图片引用，并在对应讲解附近写出具体 `图片描述` 注释。
2. **插图阶段**：再由 `subject-illustrations` 或其他制图流程生成图片并插入注释上方。插入图片后仍须保留注释，不能用图片替代注释。

图片注释格式必须使用：

```markdown
<!-- 图片描述：详细说明图片要表现的段落核心内容；说明图片内容、结构、元素、标注文字、关系箭头、关键过程、视觉重点；说明该图如何帮助理解当前小节或段落；说明符合本学科图片风格约束。 -->
```

图片注释要求：

- 每个子章节文件开头必须配置一张“本节整体知识信息结构图”注释，放在标题后或 `本节学习目标` 前后，用于展示本小节知识对象、核心概念、方法流程、关系结构、重点难点和题型应用的整体框架。它不是全章总图，而是本小节的学习导航图。
- 子章节不能只有一张泛泛的图。除开头整体知识信息结构图外，还应在 `核心知识点讲解` 和 `重点梳理` 中围绕核心知识、方法流程、概念关系、符号/公式关系、实验/材料结构或题型路径补充必要图片注释，做到真正图文并茂。
- 对于定义密集、关系复杂、流程明确、公式推导、模型建构、实验过程、图表判读、题型方法等内容，优先用图片注释表达“方法、流程、关系”，而不是只给静态概念图。
- 注释放在需要插图的段落、表格、模型、实验、文本分析或例题讲解附近，位置要服务当前段落的核心内容。
- 注释必须具体到可指导生图，不能只写“配图”“示意图”“流程图”等空泛词。
- 注释要说明图中应出现的主要对象、结构层次、箭头关系、标注文字、关键变量、过程顺序、对比维度或核心结论。
- 注释要体现当前小节内容，不要生成与段落无关的装饰图、封面图或泛泛背景图。
- 同一篇笔记中的图片注释要遵循对应学科参考文件的 `图片风格约束`，保持配色、线条、标注方式、版式和视觉语言一致。
- 源文中每个有学习价值的图片、图表、地图、实验装置、结构图、函数图像、流程图或照片等视觉单元都必须有一个对应的、可追溯的图片注释；多面板图可按语义合并，但不能漏掉有独立知识含义的面板。保留原图号/图题，或在注释中明确“对应源文图X”。
- “每节整体图 + 2–5 张局部图”只适用于源文没有可盘点图片的普通内容；只要源文存在图表清单，就以源文视觉单元数量和学习价值为准，不得用 2–5 的上限截断源图注释。
- 图片注释可以放在 `核心知识点讲解`、`难点突破`、`例题讲解` 或 `考点考证点整理` 等最需要视觉辅助的位置；不要把所有图片注释集中堆在文末。
- 插入图片统一使用相对路径 `![图题](images/文件名.webp)`。文件名和路径不得包含空格，分隔使用 `-` 或 `_`；推荐使用 `<小节slug>-图<图号>.webp`，例如 `第一节-太阳辐射-图1-1.webp`。
- 生成的图片默认放在对应笔记目录的 `images/` 下；相同资源可以被多个笔记通过相对路径共享，不要无意义复制。每个图片引用都必须能解析到真实文件，且保留其上方或紧邻的图片描述注释。

## 学科知识图注释规则

知识图是图片注释中的重点类型，用于把概念关系、过程机制、分类层级、因果链条、题型路径或文本结构可视化。每个子章节开头必须有一张本节整体知识信息结构图；正文中的知识图则根据内容复杂度和学习价值配置。

段落或小节中的知识图注释要求：

- 本节整体知识信息结构图必须概括本小节的知识主线，但不能替代正文局部图。正文还要在关键知识点、重点梳理或难点方法处配置局部知识图，展示“这个知识点怎么理解、怎么判断、怎么计算或怎么作答”。
- 只有当某段、某个小节或某组知识点存在明显的结构关系、过程顺序、分类层级、对比关系、因果链条、公式/方程/模型关联、实验证据链或答题路径时，才插入知识图注释。
- 知识图必须服务插入位置的核心内容，展示该段落或小节最需要学生看懂的关系，而不是把整节内容泛泛画成大图。
- 知识图注释要说明图的类型，例如“分类树”“流程图”“因果链”“对比表格图”“概念关系网”“实验证据链”“题型解题路径图”“文本结构图”等。
- 知识图注释要写清节点、层级、连接线/箭头、关系词、重点标注、颜色含义和最终结论，确保后续能据此生成稳定一致的图片。
- 同一子章节文件中图片注释数量要克制但不能过少。一般应包含 1 张开头整体知识信息结构图，加上 2-5 张服务核心讲解、重点梳理、难点突破、方法流程或题型路径的局部图；内容特别长、图表/实验/模型密集时可以增加。不要为了“图文并茂”把笔记变成画册，也不要只放一张总图敷衍。
- 对简单定义、短列表、已由表格清楚表达的内容，不必强行插入知识图。

章节整体知识结构图注释要求：

- 可以在章节开头或章末的单独整合文件中，插入当前章节整体知识结构图的图片注释，用于展示本章主线、各小节关系、核心概念层级、方法链条和考点分布。
- 章节整体知识结构图不要求每章必须有；当本章知识点之间有明显层级、转化、递进、并列或综合应用关系时优先生成。
- 整体知识结构图注释应明确本章中心主题、一级分支、二级知识点、跨小节联系、重点/难点/考点标记和复习路径。
- 整体知识结构图只放在章节整合文件或章首/章末位置，不要在每个子章节文件中重复放同一张全章总图。
- 章节整体知识结构图也必须遵循对应学科参考文件的 `图片风格约束`，并与本章其他图片保持一致。

## 教材练习题收录规则

如果课本源文中有练习题、课后题、思考与讨论、探究活动、练习与应用、复习与提高或类似题目，必须在章节笔记中保留其学习价值：

- 在 `练习题` 栏目中收录教材原题或忠实改写后的完整题干；题目依赖图片、表格、实验装置或材料时，要用文字说明关键信息，不能只写“见图”。
- 每道教材题应保留题号或标明来源，如“教材练习与应用第3题”“思考与讨论第1题”，方便回查原文。
- 可以补充自拟的基础、巩固、提升题，但自拟题不能替代教材已有题目；若篇幅需要筛选，优先保留承载新方法、核心考点、易错点和综合应用的教材题，并说明筛选原则。
- 在 `练习题答案` 栏目中逐题对应给出答案、解题说明和关键步骤；选择题要说明选项判断理由，计算题要列公式和过程，实验/材料/阅读题要给出作答角度和关键表述。
- 若源文题目缺少必要图片、数据或 OCR 识别不清，仍要保留题目位置，并标注“需回看原文/图片确认”的具体信息。

## 考点整理规则

`考点考证点整理` 不是知识点名称清单。必须把每个考点写成可用于做题和答题的复习单元，推荐使用以下结构：

```markdown
### 考点一：考点名称

- 出题思路：说明命题通常如何设置情境、材料、图表、实验、文本、数据或设问。
- 关键条件：列出题目中需要抓住的关键词、已知量、限制条件、隐含条件或易混信息。
- 解答要点：写出答案中必须出现的关键词、判断依据、公式/方程式、步骤、结论或表述模板。
- 易扣分点：指出常见漏答、错判、格式错误、单位/符号错误、逻辑跳步或表述不完整。
```

理科考点的 `解答要点` 要突出建模、公式/方程式、计算步骤、条件检查和结论；文科和语言类考点的 `解答要点` 要突出材料定位、关键词提取、分析角度、答题术语和表达模板。

## Subject Structure Rule

九个顶层栏目在所有学科中保持一致，但 `核心知识点讲解`、`重点梳理`、`难点突破`、`例题讲解` 的内部结构必须遵循对应学科参考文件。

不要把文科强行写成理科公式/模型结构，也不要把理科写成松散的文字摘要。

学科结构分为三类：

- 理科统一结构：数学、物理、化学、生物。四科都按"对象/情境 -> 概念/定义 -> 规律/公式/原理 -> 模型/方法 -> 图表/实验/证据 -> 题型迁移"组织，只替换为本学科关键词。
- 文科解释结构：语文、历史。语文重在文本细读、语言审美和表达迁移；历史重在时空定位、史料证据和历史解释。
- 综合/语言结构：英语、地理。英语按语言知识、语篇理解和表达应用组织；地理按区域定位、要素综合、过程机制和图表证据组织。

理科类学科保持以下统一内部逻辑：

```markdown
### 一、知识对象与学习情境
### 二、核心概念与定义
### 三、关键规律、公式或原理
### 四、典型模型与分析方法
### 五、图像、实验或材料信息
### 六、题型应用与迁移
```

文科和语言类学科使用对应学科参考结构，不套用理科结构。

## 反模式

- 把格式化后的教材章节直接复制进 `high_school/<学科>/章节笔记/`。
- 只创建 `原始课本素材.md`，没有子章节学习笔记。
- 按页码、练习块或任意标题拆分，而不是按真实子章节拆分。
- 只写摘要、提纲或考点速记，导致教材中的核心知识点和关键内容缺失。
- 为了简洁省略必要定义、公式条件、推导过程、实验步骤、文本层次、史实背景或图表信息。
- 缺少必要图片注释，或只写空泛的 `<!-- 配图 -->`、`<!-- 示意图 -->`，没有说明图片内容、结构、元素和核心要点。
- 源文存在图号或图片引用，却没有逐一建立视觉单元与图片注释的对应关系，或插图阶段删除了原有注释。
- 子章节开头缺少本节整体知识信息结构图，或只有开头一张总图而核心知识点讲解、重点梳理、方法流程、概念关系处没有局部图。
- 图片注释只描述静态对象，没有呈现方法、流程、关系、推导、判断路径或答题路径。
- 图片注释与插入位置的段落内容无关，或同一篇笔记中的图片风格约束混乱。
- 机械地要求每个文件固定一张知识图，或在没有结构关系的短内容中强行插图。
- 图片注释数量失控，把章节笔记变成图片清单或画册，削弱文字讲解和训练内容。
- 图片文件名或引用路径含空格、图片引用不存在，或图片引用与图片描述注释无法一一对应。
- 在每个子章节文件里重复放同一张全章知识结构图，而不是放在章首或章末整合文件中。
- `考点考证点整理` 只列“考查概念、公式应用、实验题”等名称，没有说明出题思路、关键条件、解答要点和易扣分点。
- 源文有教材练习题却没有收录题目，或只写“完成教材练习”而不给题目、答案和解题说明。
- 缺少练习题答案，或答案只给最终选项/数字，没有必要推理、步骤、依据或答题要点。
- 把原始资料、脚本或临时文件混入学科笔记目录。
- 缺少 YAML frontmatter，或 `title`、`description`、`tags`、`draft` 不可被 Quartz 正确解析。
- 每篇笔记只有一个知识点标签，或用学科、章节、题型标签冒充多个知识点。
- 知识点标签与正文不对应，同一知识点使用多个近义标签，或为了凑数拆词造标签。
- 缺少 `知识关系导航`，存在悬空 Wikilink，或只堆链接而不解释知识点关系。
